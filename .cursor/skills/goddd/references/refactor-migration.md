# 重构迁移等价性验收

仅在用户要求重构或迁移时，检查本次授权范围内的新旧实现。普通维护任务不因此触发全域迁移。核心原则：

> **重构不能改变原有代码的语义。** 写法可以变（Session → WithTx、Edit → Update），行为不能变。用户要求的行为变化应与等价重构区分，单独说明影响；发现范围外的问题先报告。

## 等价性检查清单

选择本次改动涉及的条目比对新旧实现。非预期差异先修正；需要改变已约定语义时再向用户确认。

### SQL 与数据

- [ ] **WHERE 条件逐条对照**：旧 SQL 的每一个条件（含 `>=`、`<=`、IN、OR 组合、软删除）在新实现中都有对应物。参数还在接收但条件丢失 = 静默功能回归。
- [ ] **默认排序一致**：旧 `ORDER BY create_time DESC` 不能悄悄变成 `id DESC`；无排序变有排序、有排序变无排序都算语义变化。
- [ ] **过滤匹配方式一致**：标识类字段（code、phone、device_code）旧版是 `=` 精确匹配，不得放宽为 `LIKE '%x%'`。模糊匹配只在旧版本就是模糊时才允许。
- [ ] **单条查询不加隐含条件**：不得给旧版没有的查询附加时间窗、租户、状态等"优化"条件。分区裁剪等性能优化改变了结果集就是 bug——列表与详情各自保留既定的可见性和权限规则。
- [ ] **删除条件维度不收缩**：旧版 `Where("uid=? AND to_id=? AND type=?")` 三条件删除，不得退化为只靠主键内联。复合主键场景生成器的单主键 Delete 不适用，必须手写显式 Where。
- [ ] **事务边界一致**：旧版同一事务内的多步写，新版仍在同一事务（`Begin` + `WithTx` + 成功提交或失败回滚），保留各步骤的错误处理，不拆成两个事务。
- [ ] **锁语义一致**：旧版 `SELECT ... FOR UPDATE` 行锁不得丢失。

### 错误与控制流

- [ ] **错误映射一致**：旧版返回 `record not found`（最终 404/错误响应）的路径，新版不得变成 `return nil` 假成功。错误变成功是最危险的语义反转。
- [ ] **原子条件禁止上提**：旧版 `UPDATE ... WHERE status=?`（条件不命中即报错）不得改成"先 Get 再 Go 侧 if 判断再 Update"——既引入 TOCTOU 竞态窗口，又改变错误语义。状态条件必须留在 SQL 的 WHERE 里。
- [ ] **入参转换错误不丢失**：保留转换失败时的既有错误路径，不能忽略错误后拿零值继续删改。需要修正旧错误处理时，按下文的旧 bug 流程处理。

### 响应与序列化

- [ ] **空列表序列化一致**：旧接口返回 `[]` 时保持非 nil 空切片；旧接口返回 `null` 时保留该契约。新接口按项目约定选择，不能借重构改变存量响应。
- [ ] **响应结构不变**：字段名、嵌套层级、删除接口的响应体形态保持旧版一致，前端不可感知。

### 缓存

- [ ] **缓存键与 TTL 一致**：键中含全部区分维度（目标 ID 等），固定键会让不同实体的缓存互相串数据。
- [ ] **缓存失效语义一致**：对照旧实现的覆盖、失效、回填与预热行为。SetNX 和 Set 的语义不同，不能互换；缓存缺陷另行处理，不能以新规范为由静默改变。
- [ ] **事务副本只失效不重建**：事务内写操作对缓存只做 Del/墓碑，提交前不得把未提交数据写进缓存。

### 复用与旧函数清理

- [ ] **先核实等价性再复用**：确认标识的唯一范围、租户与权限约束、错误契约及排序，再复用 `GetByID`、`QueryByKey`、`List`、`Count`。字段叫 `id`、`Code`、`UUID` 并不能证明全局唯一；语义确有差异时保留专用方法。
- [ ] **识别受影响调用方**：迁移前列出已知调用点、接口实现与 Mock；只替换获准范围。检索发现范围外依赖时先报告，不能自行扩大迁移。
- [ ] **有依据地删除旧方法**：对本次替代的内部方法，确认无引用且属于授权范围后，同步移除声明与实现。公开接口还须核查仓库外消费者及兼容要求，仓库内无引用不足以证明可删。
- [ ] **保留关键注释**：把说明不变量、权限约束与竞态规避理由的注释移到对应实现。

## 发现旧 bug 时怎么办

重构中发现旧实现本身有 bug（缓存串键、条件从未生效、写入静默失败）：

1. **不在重构提交中顺手修**。先完成等价重构，保持 diff 可审查。
2. 先报告旧行为、影响及修复建议。用户已授权该修复时单独处理，否则等待授权。
3. 无法在保持旧行为的前提下完成迁移时，说明阻塞，不自动执行有行为变化的替代方案。

## 验收动作

- 在受影响的 Go module 中运行构建、静态检查及相关测试；根 module 的 `./...` 不包含嵌套 module。
- 对核心 CRUD 路径，用新旧两版各跑同一组请求比对响应（含空列表、不存在 ID、边界参数）。
