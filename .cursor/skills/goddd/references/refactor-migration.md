# 重构迁移等价性验收

重构/迁移旧代码到 goddd 架构时阅读。唯一核心原则：

> **重构不能改变原有代码的语义。** 写法可以变（Session → WithTx、Edit → Update），行为不能变。任何有意为之的行为变化，必须单独提交并在 commit message 中明说。

## 等价性检查清单

提交前逐项比对新旧实现，任何一项对不上都必须停下来确认：

### SQL 与数据

- [ ] **WHERE 条件逐条对照**：旧 SQL 的每一个条件（含 `>=`、`<=`、IN、OR 组合、软删除）在新实现中都有对应物。参数还在接收但条件丢失 = 静默功能回归。
- [ ] **默认排序一致**：旧 `ORDER BY create_time DESC` 不能悄悄变成 `id DESC`；无排序变有排序、有排序变无排序都算语义变化。
- [ ] **过滤匹配方式一致**：标识类字段（code、phone、device_code）旧版是 `=` 精确匹配，不得放宽为 `LIKE '%x%'`。模糊匹配只在旧版本就是模糊时才允许。
- [ ] **单条查询不加隐含条件**：不得给旧版没有的查询附加时间窗、租户、状态等"优化"条件。分区裁剪等性能优化改变了结果集就是 bug——列表能看到的记录，详情必须能查到。
- [ ] **删除条件维度不收缩**：旧版 `Where("uid=? AND to_id=? AND type=?")` 三条件删除，不得退化为只靠主键内联。复合主键场景生成器的单主键 Delete 不适用，必须手写显式 Where。
- [ ] **事务边界一致**：旧版同一事务内的多步写，新版仍在同一事务（`Begin` + `WithTx` + `Commit` + `defer Rollback`），不少一步、不拆成两个事务。
- [ ] **锁语义一致**：旧版 `SELECT ... FOR UPDATE` 行锁不得丢失。

### 错误与控制流

- [ ] **错误映射一致**：旧版返回 `record not found`（最终 404/错误响应）的路径，新版不得变成 `return nil` 假成功。错误变成功是最危险的语义反转。
- [ ] **原子条件禁止上提**：旧版 `UPDATE ... WHERE status=?`（条件不命中即报错）不得改成"先 Get 再 Go 侧 if 判断再 Update"——既引入 TOCTOU 竞态窗口，又改变错误语义。状态条件必须留在 SQL 的 WHERE 里。
- [ ] **入参转换错误不得忽略**：`strconv.Atoi` 等转换的 error 必须处理并返回 400。忽略错误得到零值，再拿零值去删/改数据 = 数据事故。

### 响应与序列化

- [ ] **空列表序列化为 `[]`**：列表接口空结果必须是 `"items": []` 而非 `"items": null`。返回前确保切片经 `make([]*T, 0)` 初始化。
- [ ] **响应结构不变**：字段名、嵌套层级、删除接口的响应体形态保持旧版一致，前端不可感知。

### 缓存

- [ ] **缓存键与 TTL 一致**：键中含全部区分维度（目标 ID 等），固定键会让不同实体的缓存互相串数据。
- [ ] **缓存失效语义一致**：旧版 SetNX（不覆盖）不得变成 Set（覆盖）；WarmUp 预热一律 SetNX。注释写什么，实现就必须是什么。
- [ ] **事务副本只失效不重建**：事务内写操作对缓存只做 Del/墓碑，提交前不得把未提交数据写进缓存。

### 代码纪律

- [ ] **「为什么」注释随逻辑迁移**：旧代码中表达不变量、防误杀约束、竞态规避的注释必须搬到新实现对应位置。丢注释视同丢逻辑——后人读不出约束，必会"优化"出 bug。
- [ ] **不留占位语句**：禁止 `var _ = errors.New` 之类压编译器的残留。编译告警要根治，不要掩盖。
- [ ] **每个提交编译通过**：`go build ./...` 全绿才允许 commit，半成品用 `git stash`。
- [ ] **一个 commit 只做一件事**：重构与行为修复分开提交；行为修复在 message 中写明"旧行为 → 新行为"及理由。

## 发现旧 bug 时怎么办

重构中发现旧实现本身有 bug（缓存串键、条件从未生效、写入静默失败）：

1. **不在重构提交中顺手修**。先完成等价重构，保持 diff 可审查。
2. 修复单独提交，message 写明旧行为、新行为、影响面。
3. 无法确认影响面时，向用户说明后由用户拍板，不自行决定"顺便修了"。

## 验收动作

- 逐 commit 跑 `go build ./... && go vet ./... && go test ./...`。
- 对核心 CRUD 路径，用新旧两版各跑同一组请求比对响应（含空列表、不存在 ID、边界参数）。
